# 數字森林：技術及產品決定

最後更新：2026-08-30

本文件記錄已作出且不應在沒有新證據下反覆推翻的決定。狀態可能改變的內容應寫入 `PROJECT_STATE.md`。

## D-001：試用架構採用 Cloudflare Pages ＋ Supabase

- 狀態：已採用。
- 決定：前端部署至 `Cloudflare Pages`；身份驗證及資料庫使用 `Supabase Free`。
- 原因：首輪只有一個班別，免費方案足以開始驗證；兩者都可逐步擴充而不需要先維護伺服器。
- 限制：用量、暫停、備份及免費方案條款需定期檢查，不能假設永遠免費或永不改變。

## D-002：Cloudflare 使用獨立靜態 Vite 建置

- 狀態：已採用。
- 決定：正式建置為 `npm run build`，使用 `vite.static.config.ts`，輸出 `dist/client`。
- 原因：目前產品是瀏覽器端應用；這個路徑已成功部署，並避開 `Vinext`／Sites 設定對 `.openai/hosting.json` 的依賴。
- 限制：除非有已驗證的遷移計劃，不要把正式建置切回 `vite.config.ts` 或 `build:vinext`。

## D-003：Supabase RLS 是正式資料權限邊界

- 狀態：必要原則，仍需版本化及測試。
- 決定：前端只使用 anon key；所有學生、班級、作答及報告資料由 `RLS` 限制。
- 原因：前端程式及 anon key 可被使用者查看，隱藏按鈕不能保護資料。
- 限制：禁止在瀏覽器使用 `service_role`；教師只能讀取獲授權班級，學生只能讀取自己的資料。

## D-004：學生使用數字登入名稱，Auth 內部使用電郵別名

- 狀態：已實作原型。
- 決定：非電郵登入名稱轉換為 `登入名稱@digitalforestmath.example` 後交由 `Supabase Auth` 驗證。
- 原因：學生不需要真實電郵，同時可沿用成熟的密碼驗證流程。
- 限制：內部別名不應出現在學生畫面；試用學生密碼可用教師派發的 `6` 位數字，但教師及管理員密碼仍按較高安全標準管理。

## D-005：角色分流不可只靠導覽按鈕

- 狀態：前端基本守衛已實作，後端仍需測試。
- 決定：學生不顯示教師入口，直接切換教師 route／view 時亦返回學生地圖；後端另以 `RLS` 阻止資料讀取。
- 原因：早期原型曾出現學生可看見教師畫面的問題。

## D-006：題目先核准，再進正式題庫

- 狀態：已採用。
- 決定：首版題目由教師逐題核實；未核准的題目不可發布。現時第一關內容暫存於 `lib/first-stage-content.ts`。
- 原因：教學正確性及難度配置比自動生成速度重要。
- 限制：內容進入資料庫後仍需版本、發布及封存狀態；已作答版本不可覆寫。現時第一至第四關仍保留在本機內容檔，尚未接駁正式題庫。

## D-014：第四關按個位數、兩位數及三項加法分層

- 狀態：教師已核准，前端原型已實作。
- 決定：第四關「異號加法」的 A 部分使用個位數，B 部分每題只含兩個兩位數有向數，C 部分每題含三個有向數；三部分均使用整數鍵盤。
- 原因：由較小數值的兩項異號加法，逐步增加數值位數，再過渡至三項有向數相加，維持清晰的難度梯度。
- 限制：第四關現時只在本機示範模式開放，未保存正式作答或星級；發布前仍需教師逐題抽查及在實體 `iPadOS 15 Safari` 驗證。

## D-007：每局固定為 4＋6＋3

- 狀態：產品規則。
- 決定：基礎回想 `4` 題、核心練習 `6` 題、綜合或挑戰 `3` 題，共 `13` 題。
- 原因：配合約 `10` 分鐘的短活動，並保留從回想到遷移應用的層次。

## D-008：第一關數線及題目限制

- 狀態：教師已核准現有 `10` 題。
- 決定：數線固定顯示 `−8` 至 `＋8`；Q2 使用 `−7`；C4–C6 的溫度、獲利及東西方向情境題不顯示數線。
- 原因：基礎學生需要穩定的視覺範圍，而情境題要檢查語意轉換，不應直接提供數線線索。
- 限制：挑戰題可超出一般數線範圍，但仍需教師逐題核實。

## D-009：錯誤回饋採逐層揭示

- 狀態：畫面部分完成。
- 決定：第一次錯誤指出檢查方向；第二次提供數線或符號提示；第三次顯示完整解法，然後出同技能、不同數值的補救題。
- 原因：讓學生先自行修正，再逐步增加支援；提示使用同時成為學習分析資料。
- 限制：主動開啟提示才記錄為使用提示；當局前後差異不可直接當作正式學習成效。

## D-010：星級反映支援程度，不影響答題能力

- 狀態：規則已定，持久化未完成。
- 決定：首次正確且未看完整解法為 `3` 星；提示後完成為 `2` 星；查看完整解法並完成補救為 `1` 星。
- 原因：鼓勵獨立完成，同時不把需要支援的學生排除在解鎖流程外。
- 限制：收藏及外觀不提供數學能力加成。

## D-011：不在 Git 保存個人資料或秘密

- 狀態：永久原則。
- 決定：真實姓名、學號、班別、教師電郵清單、登入資料、密碼、匯入檔案、資料庫密碼及管理員密鑰均不得提交。
- 原因：學生私隱、帳戶安全及 repository 可分享性。
- 限制：測試 fixture 必須使用虛構、去識別化資料。

## D-012：先完成核心資料循環，再整理大型 UI

- 狀態：開發次序。
- 決定：先完成內容核准、作答保存、權限、補救及報表資料，再進行大規模 UI 拆分及正式插圖。
- 原因：目前最大風險是資料、權限及教學流程，不是視覺細節；過早重寫 UI 容易破壞已完成登入及角色分流。
- 限制：可以作必要的可用性修正，但不要在沒有測試下全面重寫 `app/page.tsx`。

## D-013：第三關 H 部分只使用一位小數

- 狀態：教師已核准，前端原型已實作。
- 決定：第三關「同號加法」的 A、B 部分使用整數；H 部分的三題可使用小數，但每個小數最多只有 1 位，小數答案由數字鍵盤輸入。
- 原因：保留同號加法的核心概念，同時讓挑戰題加入受控的小數情境，避免超出首版內容範圍。
- 限制：小數限制只在第三關 H 部分適用；正式發布前仍需教師逐題抽查及在實體 `iPadOS 15 Safari` 驗證。
